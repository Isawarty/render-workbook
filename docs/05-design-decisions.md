# 设计决策与理由

这门课的形态是拷问出来的，不是拍脑袋定的。这里记的是**当初为什么这么选**，
以及后来哪些结论被推翻了。

roadmap（`00-roadmap.md`）说的是「做什么」，这份说的是「为什么」。
当你以后想「当初干嘛不直接用 X」的时候，翻这里。

---

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 宿主语言 | C++17 + CMake + CMakePresets | 资料最厚；Lua C API 天然契合；求职直接对口 |
| Shader | P1–P3 用 GLSL，**P4-t07 起迁 Slang** | GLSL 复用 OpenGL 底子，先不加新语言的负担；Slang 一份源码出 SPIR-V / DXIL / Metal，语法≈HLSL 超集，求职价值不丢，而且是 P7 那份 Vulkan↔D3D12 对照表的前提 |
| 依赖 | CMake FetchContent，**全部锁 SHA256** | 一行 `cmake --preset` 三台机器一致 |
| 测试 | 三层（validation / readback / golden） | 唯一在 NVIDIA + Apple Silicon 两边都站得住的方案 |
| CI | GitHub Actions + Mesa lavapipe | 纯 CPU 软件渲染 = 确定性像素，golden image 才可能严格判分；顺带绿色徽章 |
| 文档 | 任务书中文，顶层 README 英文 | 学习用母语最快；GitHub 首页给招聘方看 |

**零 SDK 即可编译**是刻意的：Vulkan-Headers / volk / glslang 也走 FetchContent，
所以任意机器 clone 后立刻能编译。Vulkan SDK 只在**想跑 L1 判分**时才需要
（它提供 validation layer）。这一条让「换台机器试试」的成本接近零。

## 课程形态

**为什么是「代码挖空」而不是照着教程抄一遍**
抄一遍的问题是你不知道自己哪里没懂 —— 抄完能跑，隔一周重写不出来。
挖空 + 自动判分把「以为懂了」和「真的懂了」分开。

**为什么 P1 要从空 `main()` 写起，而且只有这一次**
Vulkan 初始化写第一遍是理解，写第四遍是打字。所以 P1 全挖空、痛一次，
之后那些代码提炼进 `engine/rhi/`，从 P2 起是框架不是考点。
> 挖空策略是**先细后粗**：项目 1 连 instance 创建都挖，之后复用你自己写过的代码。

**为什么用「官方基线」而不是让你一路带着自己的实现走**
每题结束后切回参考实现再进下一题。代价是明确的、也是当初就接受了的：
**你自己的实现每题会被覆盖，最终框架不是逐行「完全自己写的」**。
两条缓解措施：
1. `mine/pXX-tN` tag 完整保留你每一题的实现，作品集叙事靠它;
2. P5（Render Graph）和 P6（Lua 嵌入）的架构部分**不给强基线**，只给接口契约和测试
   —— 那两段是真正自由发挥的，也是面试最能聊的。

**为什么不是每题一个分支**
40 个 task 会变成 80 个分支，而且 task N 的骨架**必然包含** N-1 的答案，
分支隔离本来就无效。改成两个长期分支 + tag（见 `02-git-workflow.md`）。

## 被推翻的原始计划

写在这里是为了别再走一遍回头路。

**Vulkan 的终点从「GPU-driven」降到「延迟渲染 + Render Graph」。**
连带后果：Compute Shader 从「顺手带过」重新独立成 P3。
这是好事 —— compute 是全套里判分最硬的一段（100% 确定性的 L2），
挂在别人后面当配角太浪费。

**DirectX 从「跨平台三件套之一」降级成 Windows-only 的概念打通项目（P7）。**
macOS 上根本没有 D3D12，硬要它参与跨平台约束会污染整个 CMake 结构。
降级之后它成了唯一没有前置依赖的项目 —— **想提前做随时可以**。
真做到 P4 时如果觉得 Vulkan 记忆还热乎、想趁热做对照表，就提前。

**Lua 从零开始**（当初以为有基础，拷问出来是完全不会），
所以拆成「t00 语言速通」（20 道纯 Lua 小题，无挖空，约 2 周）+ 引擎嵌入两段。

## 交付之后改掉的

| 改动 | 原因 |
|---|---|
| 仓库名 `gpu-lab` → `render-workbook` | — |
| ImGui 集成从 P2-t07 挪到 **P5-t06** | 它的 Vulkan backend 是体力活，教不了 Vulkan 概念；P5 才真的需要一个面板。腾出的位置把原 t04 拆成「image + transition」和「view + sampler + mipmap」两题，粒度更匀 |
| 判分加第四档「**结构比对**」 | t05 之后画面依赖纹理过滤，各向异性是厂商私有实现，NVIDIA 和 lavapipe 差到 lenient 容差也救不了 —— 但那不代表实现错。真实 GPU 上退化成 16×16 块比平均色，严格逐像素留给 CI |
| 加统一入口 `rwb.py` | 三条平台相关的 cmake/ctest 命令收成一条，自动挑 preset |
| 加 `04-course-authoring.md`（**从 P3 起生效**） | 明确「不按代码行数拆题」，以及检查点的准入条件 |
| **不给 P1/P2 做检查点改造** | 它们在规范之前就完成并逐 tag 验证过了，为对齐规范去重建提交链不划算。目前仓库里一个检查点也没有 |

## 已知风险（当初就写明、现在依然成立）

1. **12–15 个月是真实周期，不是保守估计。** 光 P1 就 35–45 小时，
   前三四周可能只有一个三角形。这是「先细后粗」必然的代价，也是它值钱的原因。
2. **MoltenVK 不是完整的 Vulkan**：无 geometry shader、subgroup 能力受限、
   bindless 受限、部分格式不支持。**P3-t02（并行归约 / subgroup）和 P4 的部分特性
   需要 macOS 降级路径**，对应 task 里必须写明并给 fallback。
3. **官方基线削弱「完全自己写」的叙事**（已接受，见上）。
4. **P7 与 Vulkan 主线隔了大半年**，届时记忆可能已经模糊，对照表的价值打折。
   它没有前置依赖，想提前就提前。
